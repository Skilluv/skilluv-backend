# Manifeste du domaine Code

*Destiné à être publié sur `skill-uv.com/code/manifesto`.*

La [charte](./CHARTER.md) dit ce qui est exigé. Ce texte dit pourquoi.

---

## Le problème n'est pas qu'il manque des formations

Il en existe des milliers. Le problème est que **personne ne sait ce que les
gens savent faire**.

Un CV est une déclaration. Un certificat atteste qu'un examen a été passé, pas
qu'un travail a été livré. Une plateforme d'exercices mesure la capacité à
résoudre des exercices — ce qui est une compétence réelle, et pas celle qu'on
achète quand on recrute.

Nous partons de l'autre bout : **l'artefact d'abord**. Ce qui compte est ce
qui existe et que quelqu'un peut ouvrir.

## Sept partis pris

### 1. Le code est un artefact opposable

Une contribution acceptée, un projet en service, une bibliothèque publiée. Pas
un exercice terminé.

La distinction n'est pas le niveau de difficulté : c'est qu'un inconnu peut
vérifier sans vous croire. Un exercice de tutoriel prouve que le tutoriel a
été suivi.

### 2. L'open source d'abord

Une contribution en amont vaut plus qu'un dépôt privé de qualité égale, parce
qu'elle a franchi le jugement de quelqu'un qui n'avait aucune raison d'être
indulgent.

C'est aussi le seul terrain où un développeur d'Abomey et un développeur de
Berlin sont jugés sur la même chose. Le mainteneur qui lit la proposition ne
sait pas d'où elle vient et ne s'en soucie pas.

### 3. L'itération est pédagogique, pas punitive

Un refus est le début d'un tour suivant. Le relecteur dit lequel des critères
n'est pas atteint et ce qui manque.

Un métier s'apprend en le pratiquant sous le regard de quelqu'un qui l'exerce
déjà. C'est du compagnonnage, pas un examen : l'objectif est que le second
essai soit meilleur, pas de trier au premier.

### 4. Les métiers ne sont pas des cases

Une personne fait du web et du jeu, du système et de l'IA. Le catalogue
compte trente-trois métiers du code parce que « développeur backend » désigne
une famille et non un métier — mais rien n'oblige à en choisir un seul, et
passer de l'un à l'autre n'est pas de la dispersion.

### 5. Les tests font partie du travail

Pas un supplément. Un livrable sans test décrit une intention ; avec des
tests, il décrit un comportement.

Nous valorisons les tests qui survivent au remaniement — ceux qui décrivent ce
que le code doit faire, pas comment il est écrit aujourd'hui.

### 6. La documentation est obligatoire

C'est la règle qui écarte le plus de soumissions, et elle ne bougera pas.

Un code que personne ne peut reprendre n'a pas de valeur pour un employeur,
un mainteneur, ni pour vous dans six mois. Savoir écrire ce qu'on a fait fait
partie de savoir le faire.

### 7. L'IA se déclare

Elle est utilisée. Elle sera de plus en plus utilisée. Prétendre l'interdire
produirait des déclarations fausses, pas des pratiques différentes.

Ce qui se juge est le résultat et votre capacité à en répondre : expliquer un
choix, modifier le code devant quelqu'un. Un travail que vous ne pouvez pas
défendre ne vaut rien, qu'il ait été écrit par vous, par un assistant ou par
les deux.

---

## Ce que nous ne promettons pas

Nous ne promettons pas un emploi. Nous ne promettons pas qu'un badge vaut un
diplôme. Nous ne vendons pas de classement.

Nous promettons une chose : que ce qui est affiché sur un profil a été fait,
et qu'un inconnu peut aller le vérifier.
