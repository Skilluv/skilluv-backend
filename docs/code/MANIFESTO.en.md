# Code Manifesto

*Intended for publication at `skill-uv.com/code/manifesto`.*

The [charter](./CHARTER.md) says what is required. This says why.

---

## The problem is not a shortage of training

There are thousands of courses. The problem is that **nobody knows what
people can actually do**.

A CV is a claim. A certificate attests that an exam was passed, not that work
was delivered. An exercise platform measures the ability to solve exercises —
a real skill, and not the one anybody buys when they hire.

We start from the other end: **the artefact first**. What counts is what
exists and what somebody can open.

## Seven positions

### 1. Code is evidence somebody can check

An accepted contribution, a project in service, a published library. Not a
finished exercise.

The distinction is not difficulty: it is that a stranger can verify it without
believing you. A tutorial exercise proves the tutorial was followed.

### 2. Open source first

An upstream contribution is worth more than a private repository of equal
quality, because it passed the judgement of somebody with no reason to be
generous.

It is also the only ground where a developer in Abomey and a developer in
Berlin are judged on the same thing. The maintainer reading the pull request
does not know where it came from and does not care.

### 3. Iteration teaches; it does not punish

A rejection is the start of the next round. The reviewer says which criterion
is not met and what is missing.

A trade is learned by practising it under the eye of somebody who already
works in it. That is apprenticeship, not an exam: the point is that the second
attempt is better, not that the first one sorts people.

### 4. Trades are not boxes

One person does web and games, systems and AI. The catalogue names
thirty-three code trades because "backend developer" describes a family rather
than a trade — but nothing requires choosing only one, and moving between them
is not a lack of focus.

### 5. Tests are part of the work

Not an extra. A deliverable without tests describes an intention; with tests,
it describes a behaviour.

We value tests that survive a refactor — the ones that describe what the code
must do, not how it happens to be written today.

### 6. Documentation is required

It is the rule that turns away the most submissions, and it is not moving.

Code nobody can pick up is worth nothing to an employer, to a maintainer, or
to you in six months. Being able to write down what you did is part of being
able to do it.

### 7. AI is declared

It is used. It will be used more. Pretending to forbid it would produce false
declarations, not different practices.

What is judged is the result and your ability to answer for it: explaining a
choice, changing the code in front of somebody. Work you cannot defend is
worth nothing, whether you wrote it, an assistant wrote it, or both.

---

## What we do not promise

We do not promise a job. We do not promise that a badge is worth a degree. We
do not sell rankings.

We promise one thing: that what a profile shows was actually done, and that a
stranger can go and check.
